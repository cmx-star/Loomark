# 公司安全规范

## 敏感信息

- 不读取、输出、提交或转述密钥、令牌、私钥、证书材料和 `.env` 内容。
- 示例使用明确的占位符，不复用真实账号、域名、客户数据或内部凭据。
- 日志、错误信息、截图和文档中不得包含可用于访问内部系统的信息。

## 权限和外部操作

- 提权、生产变更、数据删除、远端推送和发布必须获得明确授权。
- 不通过关闭校验、扩大权限或绕过审批来解决工具失败。
- 外部服务调用前确认数据边界、网络可用性和目标环境。

## 数据和配置

- 修改持久化数据、配置语义或迁移逻辑前说明兼容性和回滚方式。
- 不把内部配置默认值硬编码到公共代码或公共模板。
- 涉及客户、地区或部署差异时读取项目版本规则并确认数据边界。

## 供应链

- 依赖来源、版本和安装命令必须可核验。
- 不执行来源不明的脚本或将远程内容直接送入 Shell。
- 新依赖需要说明维护状态、许可证、运行时影响和可替代方案。

## 安全问题交付

- 描述触发条件、影响范围、修复证据和未覆盖风险。
- 避免在公开文档中提供可直接利用的内部细节。
- 需要轮换凭据或处置生产数据时，交由有权限的负责人执行。
