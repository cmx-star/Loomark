# 跨平台基础GUI设计

## 目标

先交付跨平台 Markdown 编辑器的基础 GUI 首版：单窗口内完成打开、编辑、预览、保存。

首版构建环境优先落在 macOS，但产品目标保持跨平台，不引入 mac 专属行为。

## 已确认事实

- 仓库已有标准 C++20 核心层，包含文件档位、字节读取、原子写入、预览索引、字面串搜索和字节位置定位。
- 当前可用的 Homebrew 依赖里，`qtbase` 已安装，`qtdeclarative` 仍不稳定，因此首版 GUI 采用 `Qt Widgets` 更快落地。
- 现阶段目标不是高性能大文件编辑，而是先做出可见的基础 GUI 结果。

## 架构

### 应用层

- 使用 `QApplication` 和 `QMainWindow` 作为桌面入口。
- 主窗口包含菜单栏、工具栏、状态栏和中央分栏区域。
- 编辑区使用 `QPlainTextEdit`，预览区使用 `QTextBrowser`。
- 左右/上下分栏先固定为单窗口双栏布局，后续再演进为 QML 或更复杂视图。

### 文档流

1. 打开文件时读取 UTF-8 文本并显示到编辑区。
2. 编辑区 `textChanged` 时刷新预览区。
3. 保存时将编辑区内容通过核心层原子写入磁盘。
4. 文件名、大小档位、脏状态显示在状态栏或标题栏。

### 复用边界

- 复用 `src/core/document_file.*` 的 inspect、原子写入与文件档位判断。
- 预览渲染优先使用 `QTextBrowser::setMarkdown`，不引入 WebView。
- GUI 不直接依赖搜索/定位命令行逻辑，但会保留核心层后续接入点。

## 关键取舍

- 选择 `Qt Widgets` 而不是等 `QtDeclarative`，原因是当前环境已经有 `qtbase`，可以更快交付可见窗口。
- 这样做的代价是首版不是 QML 版，但不会阻断跨平台目标。
- 预览先按标准 Markdown 子集渲染，复杂块和大文件虚拟化留给后续阶段。

## 风险与缓解

- 风险：首版使用 `QPlainTextEdit`，对超大文件不是最终形态。
  缓解：把这轮范围明确限制为基础 GUI，可视结果优先。
- 风险：Markdown 预览能力取决于 Qt 文本引擎的支持范围。
  缓解：首版以基础 Markdown 预览为主，复杂语法后续再补。
- 风险：Qt 依赖在不同平台上的发现路径不同。
  缓解：macOS preset 先固定本机 Homebrew 路径，后续再补其他平台配置。

## 验收锚点

- 能启动桌面窗口。
- 能通过菜单打开本地 Markdown 文件。
- 能在编辑区修改并保存。
- 能在预览区看到当前文档内容。
- 全过程不依赖 WebView。
